Uma automação é um agente que roda sozinho. Quando o gatilho que você escolheu acontece, o agente lê os repositórios de contexto, verifica se a documentação precisa mudar e, se precisar, faz a atualização.

## Como funciona

1. Um gatilho inicia a execução.
2. O agente analisa os repositórios que você configurou como contexto.
3. Se encontrar algo para atualizar, aplica a mudança no modo que você escolheu: merge direto ou pull request.
4. Se não encontrar nada, a execução termina sem mudanças e sem cobrar créditos.

## Qual gatilho usar

Escolha o gatilho pelo evento que indica que a documentação ficou desatualizada.

| Gatilho | Use quando | Exemplo |
|---|---|---|
| Atualização de conteúdo | Uma página muda e outras dependem dela | Manter as traduções alinhadas com a página original |
| Alteração de código | A documentação descreve um código que muda com frequência | Atualizar a referência de API quando um endpoint muda |
| Agendamento personalizado | Não existe um evento claro e faz sentido revisar de tempos em tempos | Revisão mensal de exemplos e links |
| Integração | O evento acontece fora do repositório. Disponível só no plano Custom | [CONFIRMAR quais integrações] |

<Tip>
Se existe um evento ligado à mudança, prefira o gatilho desse evento. Com agendamento, a documentação fica desatualizada até a próxima execução.
</Tip>

## Merge direto ou pull request

No modo **pull request**, o agente abre um PR e alguém do time revisa antes de publicar. No modo **merge direto**, a mudança vai para a documentação sem revisão humana.

<Warning>
Use merge direto só em conteúdo de baixo risco, em que um erro publicado não cause problema. Em traduções, referência de API e conteúdo voltado para clientes, use pull request.
</Warning>

Se é a sua primeira automação, comece com pull request. Assim você vê o que o agente costuma mudar antes de decidir se confia no merge direto.
